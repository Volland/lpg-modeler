## ADDED Requirements

### Requirement: Applying a script to a running Neo4j

`lpg apply <script> --target neo4j --uri <bolt-uri>` SHALL run each statement of a neo4j script against the instance, in file order, in its own auto-commit transaction, and print each statement as it succeeds. It SHALL stop at the first failing statement, report that statement's position, its text and the engine's message, report how many statements had already been applied, and exit non-zero. Credentials SHALL be taken from `--user` and from the `NEO4J_PASSWORD` environment variable, never from a flag holding the password.

#### Scenario: Applying a generated schema to a fresh instance

- **WHEN** the neo4j script generated for a model is applied to an empty instance
- **THEN** every statement runs, the command exits zero, and the instance holds the constraints and indexes the script declares

#### Scenario: A constraint the stored data violates

- **WHEN** a script creates a uniqueness constraint on a property two stored nodes share
- **THEN** that statement is reported with the engine's message naming the conflict, the constraint is not created, no later statement runs, and the command exits non-zero

#### Scenario: Re-applying a generated schema

- **WHEN** a generated neo4j schema script is applied twice to the same instance
- **THEN** the second run changes nothing and exits zero, because every statement the generator writes carries `IF NOT EXISTS`

### Requirement: Apply checks the edition before it connects

`lpg apply --target neo4j` SHALL read the instance's edition and SHALL refuse, before running any statement, a script whose constraints require Neo4j Enterprise when the instance is Community. The refusal SHALL name the statements that cannot run there.

#### Scenario: An enterprise script against a Community instance

- **WHEN** a script generated with `--edition enterprise` is applied to a Community instance
- **THEN** an `apply-edition` error names the existence or node key constraints that Community cannot create, nothing is applied, and the command exits non-zero

## MODIFIED Requirements

### Requirement: Apply refuses scripts it should not run

`lpg apply` SHALL refuse, before connecting, a script whose header names a target other than the one requested, and a file that is not a script generated by this tool. It SHALL also refuse a script that contains statements marked destructive, unless `--allow-destructive` is given. A header naming a target with its engine in parentheses SHALL be read as naming that target.

#### Scenario: Script for another target

- **WHEN** a neo4j migration script is applied with `--target memgraph`
- **THEN** an `apply-target-mismatch` error is reported and no connection is made

#### Scenario: Destructive migration without the flag

- **WHEN** a migration containing a statement marked destructive is applied without `--allow-destructive`
- **THEN** a `destructive-change` error names the marked element and nothing is run

#### Scenario: Target that cannot be applied

- **WHEN** `lpg apply` is run with a target that has no deployment support
- **THEN** an `apply-unsupported` error names the targets apply does support
